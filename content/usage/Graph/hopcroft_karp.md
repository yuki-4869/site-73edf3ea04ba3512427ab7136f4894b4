# 二部最大マッチング（Hopcroft–Karp）

[説明書の目次](../index.md) · [コード](../../../Graph/hopcroft_karp.cpp)

左右2つの頂点集合の間で、同じ頂点を2回使わずに選べる辺数の最大値を求めます。
仕事と担当者の割当、置けるマスを行・列で表したルークの配置、二部グラフ上のドミノ配置などに使えます。
最大マッチングの対応先と辺一覧に加え、すべての辺の少なくとも一端を含む「最小頂点被覆」も復元できます。

Hopcroft–Karp法で最短の増加路をまとめて処理します。探索は再帰を使わないため、長い交互路にも対応します。
型エイリアス・マクロとコードの置き方は [共通設定](../common.md) を参照してください。
基本テンプレートの標準ヘッダーだけで使え、追加のincludeやACL本体への依存はありません。

## 型・記号・前提

```cpp
class HopcroftKarp;
```

- NLは左の頂点数、NRは右の頂点数、N=NL+NR、Mは追加した辺数です。
- `0 <= NL,NR <= INT_MAX` とし、必要なメモリを確保できることを前提とします。
- 左は `0..NL-1`、右は `0..NR-1` と、それぞれ独立した0-indexedの番号を使います。`add_edge(0,0)` は左0と右0の辺で、自己ループではありません。
- 入力は無重みの二部グラフです。一般のグラフを渡したい場合は、先に二部性を判定し、左右の番号へ振り直してください。
- 孤立点・多重辺・左右いずれかが0頂点の場合にも対応します。Mには重複して追加した辺も数えます。
- 各頂点が選べる相手は高々1個です。辺の削除、重み付きの最適化、一般グラフのマッチングは扱いません。

最大マッチングや最小頂点被覆は複数存在する場合があります。どの最適解になるかは辺の追加順にも依存します。

## コンストラクタ

```cpp
HopcroftKarp hk;
HopcroftKarp hk(int n_left, int n_right);
```

引数なしでは左右とも0頂点、2引数では左n_left個・右n_right個、辺0本で初期化します。
左右の頂点数は構築後に変わりません。

**計算量**

時間・初期領域O(N+1)。引数なしはO(1)です。

## HopcroftKarp::left_size

```cpp
int left_size() const;
```

左の頂点数NLをO(1)で返します。

## HopcroftKarp::right_size

```cpp
int right_size() const;
```

右の頂点数NRをO(1)で返します。

## HopcroftKarp::add_edge

```cpp
void add_edge(int u, int v);
```

左uと右vの辺を1本追加します。`0 <= u < NL`、`0 <= v < NR` が必要です。返り値はありません。
同じ辺を複数回追加しても構いませんが、辺を重ねることで同じ頂点を複数回使えるようにはなりません。

すでに計算した対応は保持します。次のmax_matching、mate_left、mate_right、matching、min_vertex_coverの呼び出し時に、追加辺を含む最大マッチングへ更新します。

**計算量**

償却O(1)、追加領域O(1)です。

## HopcroftKarp::max_matching

```cpp
int max_matching();
```

現在の全辺に対する最大マッチングの辺数を返します。以前からの**合計数**であり、今回新しく増えた数ではありません。
辺0本、または左右いずれかが0頂点なら0です。
計算した対応は内部に保存し、辺を追加しなければ再利用します。

**計算量**

- 未計算、または辺の追加後に最大化する1回は、最悪 $O(1+(N+M)\sqrt{N+1})$ 時間、作業領域O(N+1)。
- 変更がない状態での再呼び出しはO(1)。
- すでに小さい側の全頂点が対応済みなら、辺の追加後でもO(1)で確定します。
- 辺の追加と再計算を何度も交互に行う場合、上の計算量は各回にかかります。全操作を合計した計算量ではありません。

## HopcroftKarp::mate_left

```cpp
int mate_left(int u);
```

最大マッチングにおける左uの相手の右番号を返します。対応先がなければ-1です。
`0 <= u < NL` が必要です。未計算・辺の追加後なら、先にmax_matching相当の最大化を行います。

最大化が済んでいればO(1)です。それ以外はmax_matchingの計算量が加わります。
自動で計算状態を更新するため、constメソッドではありません。

## HopcroftKarp::mate_right

```cpp
int mate_right(int v);
```

最大マッチングにおける右vの相手の左番号を返します。対応先がなければ-1です。
`0 <= v < NR` が必要です。未計算・辺の追加後なら、先に最大化します。

最大化後はO(1)で、それ以外はmax_matchingの計算量が加わります。constメソッドではありません。

## HopcroftKarp::matching

```cpp
vector<pair<int,int>> matching();
```

最大マッチングの各辺を `(左番号,右番号)` として格納したvectorを返します。
左番号の昇順で、どの頂点も高々1回だけ現れます。要素数はmax_matchingの返す値と一致します。
未計算・辺の追加後なら先に最大化します。返されたvectorを書き換えても内部の対応は変わりません。

最大化後はO(NL+1)時間、返り値の領域は対応数をKとしてO(K+1)です。
必要ならmax_matchingの計算量が加わります。

## HopcroftKarp::min_vertex_cover

```cpp
pair<vector<int>,vector<int>> min_vertex_cover();
```

すべての辺の少なくとも一端を含み、頂点数が最小となる集合を返します。
firstは選んだ左番号の昇順の列、secondは選んだ右番号の昇順の列です。
孤立点は含めません。未計算・辺の追加後なら先に最大化します。

二部グラフでは、この2列の要素数の和が最大マッチングの辺数と一致します。
また、被覆に含まれない左右の頂点全体は最大独立集合になります。
独立集合は、その中の2頂点を結ぶ辺を含まない頂点集合です。

最大化後はO(N+M+1)時間、作業・返り値の領域はO(N+1)です。
必要ならmax_matchingの計算量が加わります。結果自体は呼び出すたびに作り直します。

## コピー・ムーブ・寿命

```cpp
auto copy = hk;
copy = hk;
auto moved = std::move(copy);
```

コピーは辺と現在の対応を独立に複製します。一方に辺を追加しても、もう一方は変わりません。
ムーブ元は左右0頂点・対応数0になり、空の取得操作と別のグラフの代入が可能です。

コピー構築はO(N+M+1)、ムーブ構築はO(1)です。
コピー代入・ムーブ代入には、上記に加えて代入先の以前の領域を解放するコストがかかります。
保持領域と破棄時間はO(N+M+1)です。

## 使用例

実装をグローバルに置き、以下をmain内などで実行します。

```cpp
HopcroftKarp hk(3,3);
hk.add_edge(0,0);
hk.add_edge(0,1);
hk.add_edge(1,0);
assert(hk.left_size()==3 && hk.right_size()==3);
assert(hk.max_matching()==2);
assert(hk.mate_left(2)==-1);
hk.add_edge(2,2);
assert(hk.max_matching()==3);
assert(hk.max_matching()==3);
auto pairs=hk.matching();
assert((pairs==vector<pair<int,int>>{{0,1},{1,0},{2,2}}));
assert(hk.mate_left(0)==1);
assert(hk.mate_right(0)==1);
auto [cover_left,cover_right]=hk.min_vertex_cover();
assert((cover_left==vector<int>{0,1,2}));
assert(cover_right.empty());

HopcroftKarp star(3,1);
for(int u=0;u<3;++u)star.add_edge(u,0);
auto [left,right]=star.min_vertex_cover();
assert(left.empty() && right==vector<int>{0});
assert(star.max_matching()==1);

auto copy=hk;
assert(copy.matching()==hk.matching());
HopcroftKarp empty;
assert(empty.max_matching()==0 && empty.matching().empty());
```

### 割当・グリッドへの対応

仕事を左、担当者を右に置き、担当可能な組に辺を追加すれば、実行できる仕事数の最大値が求まります。
すべての左頂点へ割り当てられるかは `hk.max_matching() == hk.left_size()` で判定できます。

ルークを置けるマスを行と列の辺にすると、互いに攻撃しない配置はマッチングに対応します。
障害物で攻撃が遮られる場合は、行・列そのものではなく、障害物で区切った各連続部分を頂点にします。

上下左右に隣接する2マスへドミノを置く場合は、`(行+列)%2` で左右に分け、使用可能な隣接マス間へ辺を追加します。
マッチングの1辺が1枚のドミノに対応します。

## アルゴリズム

未対応の左頂点から、未採用の辺を左→右、採用済みの辺を右→左に進む道を考えます。
未対応の右頂点まで到達すると増加路になり、道上の辺の採否を反転させることで対応数を1増やせます。

BFSで最短増加路の層を作り、同じ層の中で増加路をまとめて探します。
左頂点ごとの探索位置を進めて辺の走査を共有し、探索に失敗した頂点はその層で打ち切ります。
最短増加路を使い切るたびに次の増加路は長くなり、最悪O(√N)段階で最大化できます。
この実装はDFS相当の処理にもvectorの明示スタックを使い、関数再帰を使いません。

最小頂点被覆は、最大化後に未対応の左頂点から交互路で到達できる頂点を調べます。
到達可能な左右の集合をZL、ZRとすると、`(左全体-ZL) ∪ ZR` が被覆です。
被覆には各マッチング辺からちょうど1頂点が入り、頂点数はマッチング辺数と等しくなります。
どの被覆にも各マッチング辺の端点が少なくとも1個ずつ必要なので、この被覆が最小です。

## 入力検査

負の頂点数や範囲外の添字は、メッセージなしで停止します。NDEBUGでも検査は有効です。
メモリを確保できること、呼び出し引数がintで表せることは利用側の前提です。

## 確認結果

C++23で、左右各0〜4頂点の全74,963グラフを、部分集合DPによる独立した全探索と比較しています。
最大対応数、復元した辺の存在・端点の一意性、全辺の被覆、最小頂点被覆と最大マッチングの大きさの一致を確認しています。
さらにACLの最大流とのランダム比較、36,000回の辺の逐次追加、多重辺、コピー・ムーブ・左右0頂点を検証しています。
左右各200,000頂点の長い増加路も検証し、再帰を使わずに処理できることを確認しています。
専用テストはサイト用リポジトリの `tests/hopcroft_karp_test.cpp` です。
